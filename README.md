# TaskFlow — Smart To-Do List Manager

A responsive, light-themed full-stack To-Do List mini-project built with HTML, CSS, vanilla JavaScript, Node.js, Express, Mongoose, and MongoDB Atlas.

## Features

- Create, view, edit, and delete tasks
- Mark tasks complete and reopen them
- Search titles and descriptions
- Filter by status and priority
- Sort by creation date, due date, or priority
- Live task statistics and completion percentage
- Responsive light-themed interface
- Server-side validation and safe text rendering
- MongoDB Atlas persistence

## Requirements

- Node.js LTS and npm
- VS Code or another code editor
- A MongoDB Atlas account and a database deployment

## Setup on Windows

1. Install Node.js from https://nodejs.org/ if it is not installed.
2. Open this project folder in VS Code.
3. In the terminal, install dependencies:

   ```powershell
   npm install
   ```

4. Copy `.env.example` to a new file named `.env`. In PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

5. In MongoDB Atlas:
   - Create/select a project and a database deployment.
   - Create a database user with a strong password.
   - Add your current public IP under Network Access.
   - Open the deployment's **Connect → Drivers** option and copy the Node.js connection string.
6. In `.env`, replace the placeholder `MONGODB_URI` with the exact connection string from Atlas. Include the database name `taskflow` in the URI path, before the query string. Keep this file private.
7. Start the app:

   ```powershell
   npm run dev
   ```

8. Open http://localhost:3000 in your browser.

For a regular start without automatic restart, use `npm start`.

## Environment variables

```env
PORT=3000
MONGODB_URI=mongodb+srv://YOUR_DB_USERNAME:YOUR_DB_PASSWORD@YOUR_CLUSTER_URL/taskflow?retryWrites=true&w=majority
```

The example is a placeholder, not a working connection string. Use the URI generated by your own Atlas account. If your password contains reserved URI characters such as `@`, `:`, `/`, `?`, `#`, `[`, `]`, or `%`, percent-encode those characters in the URI. Never paste credentials into chat or commit `.env`.

## REST API

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/tasks` | List all tasks |
| GET | `/api/tasks/:id` | Get one task |
| POST | `/api/tasks` | Create a task |
| PUT | `/api/tasks/:id` | Update a task |
| PATCH | `/api/tasks/:id/toggle` | Toggle completion |
| DELETE | `/api/tasks/:id` | Delete a task |
| GET | `/api/health` | Check API and database status |

Task JSON example:

```json
{
  "title": "Complete project report",
  "description": "Finish the testing section",
  "priority": "High",
  "dueDate": "2026-11-10",
  "completed": false
}
```

## Verify the database

After creating a task, open Atlas → your deployment → **Browse Collections**. The `taskflow` database and `tasks` collection are created when the first task is saved. Verify that changes and deletions appear in the collection. Refresh the browser to confirm tasks persist.

## Troubleshooting

- **`node` or `npm` is not recognized:** Install Node.js LTS, close and reopen the terminal, then retry `node --version` and `npm --version`.
- **Missing `MONGODB_URI`:** Ensure `.env` exists in the project root and the variable name is exact.
- **Authentication failed:** Check the Atlas database username/password, not the Atlas website login. URL-encode reserved password characters.
- **IP not allowed:** Add your current public IP in Atlas Network Access. If your network changes, update the entry.
- **Cluster unavailable:** Check that the deployment is active and fully provisioned.
- **Port 3000 in use:** Set `PORT=3001` in `.env`, restart, and open `http://localhost:3001`.
- **Tasks do not persist:** Confirm the terminal says the database connected and inspect the browser Network tab for API errors.
- **Date appears one day off:** Date-only strings can be interpreted with timezone differences. The current UI formats dates using the browser locale; if exact date-only display is needed, store and render due dates as date-only values consistently.

## Project report summary

### Abstract
TaskFlow is a web-based task management application that helps users organize daily work. It provides task creation, editing, deletion, completion tracking, search, filters, sorting, and progress statistics. The frontend uses HTML, CSS, and JavaScript; Express and Node.js provide the REST API; MongoDB Atlas stores task records through Mongoose.

### Problem statement
Managing daily tasks manually can make it difficult to track priorities, due dates, and completion status. TaskFlow provides a central interface to maintain and review tasks.

### Objectives
- Build a simple, responsive task management interface.
- Implement CRUD operations through REST endpoints.
- Persist task records in MongoDB Atlas.
- Add search, filters, sorting, and dynamic statistics.
- Apply basic validation and safe rendering practices.

### Existing and proposed systems
The existing approach may rely on paper notes or disconnected lists. The proposed system keeps tasks in a single web interface with cloud database persistence and interactive status tracking.

### Requirements
**Software:** Windows, Node.js, npm, VS Code, web browser, MongoDB Atlas.  
**Hardware:** Laptop or desktop with internet connectivity.

### Architecture
Browser UI → Fetch API → Express REST routes → Mongoose model → MongoDB Atlas. Responses return to the browser, which refreshes the task list and statistics.

### Database schema
The `Task` document contains `title` (required string, max 120), `description` (string, max 1000), `priority` (Low/Medium/High), `dueDate` (optional date), `completed` (boolean), and timestamps (`createdAt`, `updatedAt`).

### Modules
1. **User interface:** Responsive layout, task forms, task cards and dialog.
2. **Task API:** Create, retrieve, update, toggle, and delete endpoints.
3. **Database:** Mongoose schema and Atlas persistence.
4. **Search and organization:** Search, status/priority filters, sorting and statistics.
5. **Validation and error handling:** Input checks, ID validation, safe DOM rendering, and readable errors.

### Advantages
- Easy to use and demonstrate.
- Persistent cloud database.
- Responsive light interface.
- Clear separation of frontend, backend, and database.

### Limitations
- No login or multi-user separation; tasks are shared by anyone who can access the app.
- Requires internet access to reach Atlas.
- This is a learning project, not a hardened production deployment.

### Future enhancements
- User registration and authentication
- User-specific task lists
- Reminders and notifications
- Recurring tasks and calendar view
- Deployment with production monitoring

### Conclusion
TaskFlow demonstrates a full-stack web application using a browser frontend, a Node.js/Express API, Mongoose data modelling, and MongoDB Atlas storage. It supports core task management and organization features suitable for a college mini-project.

## Privacy note

This version does not include authentication. It is a single shared task manager, not a private per-user application. Protect your Atlas credentials and do not expose `.env`.
