# TaskFlow — Smart To-Do List Manager

A responsive, light-themed full-stack To-Do List mini-project built with HTML, CSS, vanilla JavaScript, Node.js, Express, Mongoose, and MongoDB Atlas.

## Features

- Create, view, edit, and delete tasks
- Mark tasks complete and reopen them
- Search titles and descriptions
- Filter by status and priority
- Sort by creation date, due date, or priority
- Live task statistics and completion percentage
- Responsive light-themed interface
- Server-side validation and safe text rendering
- MongoDB Atlas persistence

## Requirements

- Node.js LTS and npm
- VS Code or another code editor
- A MongoDB Atlas account and a database deployment

## Setup on Windows

1. Install Node.js from [https://nodejs.org/](https://nodejs.org/) if it is not installed.
2. Open this project folder in VS Code.
3. In the terminal, install dependencies:

   ```powershell
   npm install
   ```

4. Copy `.env.example` to a new file named `.env`. In PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

5. In MongoDB Atlas:
   - Create or select a project and database deployment.
   - Create a database user with a strong password.
   - Add your current public IP under Network Access.
   - Open your deployment's **Connect → Drivers** option and copy the Node.js connection string.

6. In `.env`, replace the placeholder `MONGODB_URI` with the exact connection string from Atlas. Include the database name `taskflow` in the URI path, before the query string. Keep this file private.

7. Start the app:

   ```powershell
   npm run dev
   ```

8. Open [http://localhost:3000](http://localhost:3000) in your browser.

For a regular start without automatic restart, use `npm start`.

## Environment Variables

```env
PORT=3000
MONGODB_URI=mongodb+srv://YOUR_DB_USERNAME:YOUR_DB_PASSWORD@YOUR_CLUSTER_URL/taskflow?retryWrites=true&w=majority
```

The example is a placeholder, not a working connection string. Use the URI generated by your own Atlas account. If your password contains reserved URI characters such as `@`, `:`, `/`, `?`, `#`, `[`, `]`, or `%`, percent-encode those characters in the URI.

**Security warning:** Never paste credentials into chat, upload your real `.env` file, or commit database credentials to GitHub.

## REST API

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/tasks` | List all tasks |
| GET | `/api/tasks/:id` | Get one task |
| POST | `/api/tasks` | Create a task |
| PUT | `/api/tasks/:id` | Update a task |
| PATCH | `/api/tasks/:id/toggle` | Toggle completion |
| DELETE | `/api/tasks/:id` | Delete a task |
| GET | `/api/health` | Check API and database status |

## Verify the Database

After creating a task:

1. Open MongoDB Atlas.
2. Select your deployment and open **Browse Collections**.
3. Find the `taskflow` database and `tasks` collection.
4. Verify that created tasks appear in the collection.
5. Edit or delete a task and check that the changes are reflected.
6. Refresh the browser to confirm that tasks persist.

The database and collection are created automatically when the application saves its first task, assuming the database connection and permissions are configured correctly.

## Troubleshooting

- **`node` or `npm` is not recognized:** Install Node.js LTS, close and reopen the terminal, then retry `node --version` and `npm --version`.
- **Missing `MONGODB_URI`:** Ensure `.env` exists in the project root and the variable name is exact.
- **Authentication failed:** Check the Atlas database username and password, not your Atlas website login. URL-encode reserved password characters.
- **IP not allowed:** Add your current public IP in Atlas Network Access. If your network changes, update the entry.
- **Cluster unavailable:** Check that the database deployment is active and fully provisioned.
- **Port 3000 is in use:** Set `PORT=3001` in `.env`, restart, and open `http://localhost:3001`.
- **Tasks do not persist:** Confirm the terminal reports a successful database connection and inspect the browser's Network tab for API errors.
- **Date appears one day off:** Date-only strings can be interpreted differently across time zones. Store and render due dates consistently if exact date-only display is required.

## Project Report Summary

### Abstract

TaskFlow is a web-based task management application that helps users organize daily work. It provides task creation, editing, deletion, completion tracking, search, filters, sorting, and progress statistics. The frontend uses HTML, CSS, and JavaScript; Express and Node.js provide the REST API; MongoDB Atlas stores task records through Mongoose.

### Problem Statement

Managing daily tasks manually can make it difficult to track priorities, due dates, and completion status. TaskFlow provides a central interface to create, organize, update, and review tasks efficiently.

### Objectives

- Build a simple, responsive task management interface.
- Implement CRUD operations through REST endpoints.
- Persist task records in MongoDB Atlas.
- Add search, filters, sorting, and dynamic statistics.
- Apply basic validation and safe rendering practices.

### Existing and Proposed Systems

The existing approach may rely on paper notes or disconnected task lists, making it harder to track progress. The proposed system provides a centralized web interface with cloud database persistence and interactive task status tracking.

### Requirements

**Software:**
- Windows operating system
- Node.js and npm
- Visual Studio Code
- Modern web browser
- MongoDB Atlas

**Hardware:**
- Laptop or desktop computer
- Internet connectivity

### Architecture

```text
Browser UI
    |
    v
Fetch API
    |
    v
Express REST Routes
    |
    v
Mongoose Model
    |
    v
MongoDB Atlas
```

Responses return to the browser, which updates the task list and statistics.

### Database Schema

The `Task` document contains:

| Field | Description |
|---|---|
| `title` | Required task title, maximum 120 characters |
| `description` | Optional description, maximum 1000 characters |
| `priority` | Low, Medium, or High |
| `dueDate` | Optional task due date |
| `completed` | Boolean completion status |
| `createdAt` | Record creation timestamp |
| `updatedAt` | Last update timestamp |

### Modules

1. **User Interface:** Responsive layout, task forms, task cards, and dialogs.
2. **Task API:** Create, retrieve, update, toggle, and delete endpoints.
3. **Database:** Mongoose schema and MongoDB Atlas persistence.
4. **Search and Organization:** Search, status and priority filters, sorting, and statistics.
5. **Validation and Error Handling:** Input checks, ID validation, safe DOM rendering, and readable errors.

### Advantages

- Easy to use and demonstrate.
- Persistent cloud database.
- Responsive light-themed interface.
- Clear separation of frontend, backend, and database.
- Supports task organization and progress tracking.

### Limitations

- No login or multi-user separation; tasks are shared by anyone who can access the application.
- Requires internet access to reach MongoDB Atlas.
- Intended as a learning project rather than a hardened production application.

### Future Enhancements

- User registration and authentication
- User-specific task lists
- Reminders and notifications
- Recurring tasks and calendar view
- Optional dark mode
- Task analytics and productivity reports
- Cloud deployment and production monitoring

### Conclusion

TaskFlow demonstrates full-stack web development using a browser frontend, a Node.js and Express API, Mongoose data modelling, and MongoDB Atlas storage. It supports core task management and organization features suitable for a college mini-project.
